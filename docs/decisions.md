# Decisions

## 2026-11-19 — clj-replace regression tests as data-driven black-box cases

Before: clj-replace had only `evals/evals.json`, which checks whether an LLM chooses the skill, not whether `scripts/clj-replace.bb` matches correctly. Issue #3 (`#()` never matches) showed the script itself had no tests.
Decision: Add `skills/clj-replace/test/` beside `scripts/` (not inside it, so the agent does not see fixtures among the tools it runs): `cases.edn` holds one map per case (file, old, new, expected exit and file), and `run.bb` runs the script as a subprocess for each case. Cases for bugs not fixed yet carry `:known-bug true` and count as expected failures; one that passes fails the run (XPASS). A root `bb.edn` adds `bb test`. `CLJ_REPLACE_SCRIPT` points the runner at another implementation.
Reason: Issue #3 offers two fixes (normalise gensyms vs compare rewrite-clj nodes) and probing found ten more cases of the same root cause, `(= (z/sexpr a) (z/sexpr b))` not meaning "same source": false negatives (`##NaN`, `#()` in syntax-quote) and silent false positives (metadata, `#_`, vector vs list, `1` vs `1N`). Black-box cases let both fixes run against one suite: the gensym-normalising prototype turns 4 of the 11 known bugs into XPASS and leaves 7.

## 2026-11-19 — clj-replace exit 4: text present but no structural match

Before: When the structural comparison found nothing, clj-replace always printed "No matching S-expression found" (exit 2). For forms containing `#()` that reads as a typo in old-string although the text is in the file verbatim (issue #3, "distinguish the two failures"). The issue suggests detecting `#()` in old-string.
Decision: On no structural match, look for nodes whose source text equals old-string up to whitespace. If any exist, exit 4 with their locations, saying this is a clj-replace limitation and to use a plain text edit; otherwise exit 2 as before. Only the diagnosis changes; no edit is made on either path.
Reason: Detecting `#()` covers one cause; probing found at least six false negatives with different causes (`#()`, `%&`, `#()` in syntax-quote, `##NaN`), and comparing text covers them all, including ones not found yet. Comparing node text (not a raw substring search) keeps text inside comments or string literals out (`text-only-in-comment`, `text-only-in-string` cases stay exit 2). A separate exit code lets an agent switch to a text edit, which is guaranteed to find the text, instead of rewriting old-string. It does not address silent false positives (metadata, `#_`, vector vs list, `1` vs `1N`); those need the comparison itself to change. The known-bug cases now pin today's behaviour with `:interim`, so the runner notices when a bug's behaviour changes.

## 2026-11-19 — clj-replace: a different spelling of the same value is no match

Before: clj-replace compares `z/sexpr` with `=`, so code that reads to the same value matches whatever its spelling: `{:a 1 :b 2}` and `{:b 2 :a 1}`, `'x` and `(quote x)`, `#'a` and `(var a)`, `0xFF` and `255`, `1.0` and `1.00`, a string with `\n` and one with a literal line break, and a form with or without an inner `;` comment (replacing then deletes the comment). Yet `@a` does not match `(deref a)`.
Decision: clj-replace ignores layout only: whitespace, commas and line breaks between tokens. Any other difference in source, including map and set order, reader-macro versus long form, number spelling and comments, is no match. Recorded as known-bug cases in `skills/clj-replace/test/cases.edn` (`:expect {:exit 2}`, `:interim` pinning today's exit 0).
Reason: The skill promises a replacement that ignores formatting, not one that ignores spelling. Matching a different spelling replaces code the user did not write in old-string, and for inner comments it silently loses text. The equal-value cases were found by mining eastwood and splint (`resource/var-info.edn:756`, `linters/typos.clj:932`, `pattern_test.clj:33`, `priority_map.clj:353`).
